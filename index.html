实验课 1任务

实验目标：完成 Ubuntu 实验环境配置，掌握 Linux 的基本操作，为后续 ROS2 实验准备可用环境。

  1. 根据自己的电脑选择一种虚拟机方案，安装 Ubuntu 并完成软件源配置。不需要同时安装多种虚拟机；修改磁盘或虚拟化设置前，请先备份重要文件。
  2. 完成目录结构、常用终端命令和权限管理练习，保存关键命令与运行结果。遇到问题时，记录报错画面、系统与软件版本以及已经完成的步骤。
  3. 使用普通账户和 sudo 执行需要管理员权限的操作，不要启用 root 登录，也不要修改实验室公共设备的账户密码。

提前完成实验的同学：请进入第一次论文选读页面开始阅读。

第一周作业：选择一篇或多篇论文完成阅读报告，使用 Overleaf 和 LaTeX 编写并导出 PDF。报告应说明研究问题、主要方法、实验结果和个人理解，不要只翻译摘要。提交方式与截止时间以课堂通知为准。

本周任务

完成第 3 章至第 6 章项目

从节点与通信开始，逐步完成运动控制、激光雷达和 IMU 实验，并同步准备实验报告材料。

实验范围与要求

实验范围：按照第二周《第 1–7 章合并课件》，完成第 3 章至第 6 章（合并课件中的第 3 至第 6 部分）的项目，主要包括 ROS2 节点与功能包、机器人运动控制、激光雷达和 IMU。

建议项目：建议按照课件使用 WPR 系列机器人 ROS2 仿真工具。该项目面向 Ubuntu 22.04 与 ROS2 Humble，请先确认自己的环境版本。

其他平台：可以选择其他仿真机器人或真实机器人，但需要完成与课件相对应的功能，并在报告中说明机器人型号、ROS2 版本、主要话题名称以及与课件项目的差异。

实验建议：逐项运行课件示例，先确认工作空间能够编译、节点能够启动和通信，再开展运动控制、雷达与 IMU 实验。真机程序建议先在仿真中验证，运行时保持低速并确保可以随时停止。

实验报告需要保存的材料
  1. 工作空间成功编译及节点正常启动的截图。
  2. 节点、话题及通信关系的检查结果。
  3. 机器人运动控制的运行画面或结果记录。
  4. RViz 中激光雷达数据的显示效果。
  5. IMU 数据输出及关键字段的观察记录。
  6. 关键代码、参数配置或命令，以及必要的说明。
  7. 实验中出现的问题、完整报错信息和解决过程。

截图应能看清命令、窗口标题和关键结果；不要只保留最终成功画面。

实验报告建议结构与提交
  1. 实验目的：说明本次实验要掌握的 ROS2 知识与机器人功能。
  2. 实验环境：记录 Ubuntu、ROS2、仿真平台或机器人型号等信息。
  3. 实验过程：按第 3 章至第 6 章依次说明操作步骤、关键命令与代码。
  4. 实验结果：配合截图展示各项功能的运行结果。
  5. 问题与解决：记录调试过程、原因分析及解决方法。
  6. 分析与总结：总结各节点、话题和传感器数据之间的关系，以及个人理解。

提交形式：使用 Overleaf 和 LaTeX 编写，导出 PDF 后提交；具体提交方式与截止时间以课堂通知为准。

自主尝试内容

已经完成基础任务的同学，可以从第三周《第 8–10 章合并课件》中任选一个感兴趣的项目进行尝试。

  • 不要求完成全部内容，也不统一要求最终运行成功。
  • 可以按照课件使用原有机器人，也可以选择其他仿真机器人或自己的项目。

这部分用于熟悉更完整的机器人应用流程，并帮助大家发现后续希望继续学习的方向，不作为统一的强制完成项目。

所有运动控制程序应优先在仿真环境中验证。使用真实机器人时，请保持低速运行并确保能够随时停止。

10 月 8 日实验

JetAuto 真机底盘运动控制

必做

从设备检查到 ROS2 低速运动控制

识别 JetAuto 底盘的核心节点与话题，完成前进、后退、转向及停车测试，并观察 IMU 与里程计数据。

一、安全与设备检查
  1. 每组明确一名操作者和一名安全员。将机器人放在平整、无杂物的地面，预留至少 2 m 的运动空间。
  2. 检查车轮、雷达、相机和线缆是否牢固，确认电量充足。真机运动时不得将手放到车轮附近。
  3. 运动测试前打开两个终端：一个发送速度指令，另一个随时发送零速度停车指令。
  4. 先以不超过 0.10 m/s 的线速度试运行。若运动方向异常、节点报错或环境中有人进入，立即停车并断开动力。
二、连接与启动前确认
  1. 记录机器人编号、主控型号、Ubuntu 版本、ROS2 版本和连接方式。Jetson 系列可通过 NoMachine 连接；若机器人处于出厂 AP 直连模式，先连接其 HW 开头的热点，再使用 192.168.149.1 访问。若已切换局域网模式，请使用机器人当前 IP。
  2. Jetson Nano 桌面上有分别对应 ROS1 与 ROS2 的终端，请打开 ROS2 终端；不同主控和镜像可能使用不同工作环境。执行 ros2 node list 和 ros2 topic list，确认 ROS2 环境可用。
  3. 重点查找速度控制、IMU 和里程计话题。若本机话题名与课程不同，请以实际输出为准，并在报告中记录差异。
  4. 可使用 ros2 topic info /controller/cmd_vel、ros2 topic info /imu 和 ros2 topic info /odom_raw 查看消息类型与通信端点。
三、启动底盘控制

如果机器人已经运行自启 APP，先执行：

~/.stop_ros.sh

然后启动底盘控制：

ros2 launch controller controller.launch.py

启动后再次执行 ros2 node list 和 ros2 topic list，保存能够证明节点和话题已正常建立的终端输出。

四、低速运动与停车

使用 geometry_msgs/Twist 向 /controller/cmd_vel 发布指令。依次完成下列测试，每次运动 1–2 s 后立即发送零速度指令：

  1. 前进：linear.x = 0.10；后退：linear.x = -0.10。
  2. 左、右转向：设置较小的正、负 angular.z，记录对应的旋转方向。官方文档中正值为左转，负值为右转。
  3. 弧线运动：同时设置 linear.x 和 angular.z，观察轨迹变化。

停车要求：不要只在发布终端按 Ctrl+C。必须另行发布一次各分量均为 0 的 Twist 消息，目视确认机器人完全停止后再关闭节点。

速度指令参考

前进示例：

ros2 topic pub /controller/cmd_vel geometry_msgs/Twist "{linear: {x: 0.10, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}"

单次发布停车指令：

ros2 topic pub --once /controller/cmd_vel geometry_msgs/Twist "{linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}"

如果话题名不同，将命令中的 /controller/cmd_vel 替换为本机实际速度控制话题。

五、观察 IMU 与里程计
  1. 使用 ros2 topic echo /imu 观察姿态四元数、角速度与线加速度。保持车体静止后，缓慢旋转机器人，对比数据变化。
  2. 使用 ros2 topic echo /odom_raw 观察位置、姿态和速度信息。记录 frame_id、child_frame_id 及机器人前进和旋转时变化的字段。
  3. 思考编码器里程计为什么会累积误差，以及 IMU 数据如何帮助改善姿态估计。
选做

运动学分析与扩展测试

完成必做任务后，可分析轮速计算；设备确有明显偏差时再考虑标定。

麦克纳姆轮逆运动学

阅读 mecanum.py，找到车体速度 linear_x、linear_y、angular_z 转换为四路轮速的代码。说明轴距、轮距、轮径及电机安装方向对计算结果的影响。

典型解算形式为：v1 = vx - vy - ωk、v2 = vx + vy - ωk、v3 = vx + vy + ωk、v4 = vx - vy + ωk，其中 k = (wheelbase + track_width) / 2。

麦轮侧移与参数标定

麦克纳姆轮运动学模型包含 linear.y，但官方本章的速度控制操作主要演示 linear.x 与 angular.z。确认本机为麦轮底盘、支持侧移且场地允许后，可用很小的 linear.y 进行扩展测试。

官方说明整机出厂前已完成标定。只有直行或转向出现明显偏差时，才在指导教师确认后记录 calibrate_params.yaml 原始值，使用线速度或角速度标定程序测试，并每次只调整一个参数。公共设备不要自行覆盖原有标定。

验收

实验结果与报告材料

课堂内完成现场演示，同时保留能够说明过程和结果的材料。

必须完成
  1. 正确识别速度指令、IMU 和里程计话题，说明其消息类型。
  2. 以低速完成前进、后退和左右转向，并能通过零 Twist 指令可靠停车。
  3. 展示 IMU 和里程计数据，说明机器人运动时哪些字段发生了变化。
  4. 向指导教师演示一次完整流程：启动节点→发送运动指令→观察数据→发送零速度→确认停车。
报告中保留
  1. 实验环境、机器人编号、ROS2 版本与实际话题名。
  2. ros2 node list、ros2 topic list 及关键 topic info 的输出。
  3. 各种运动方式的指令、运行结果和必要的照片或短视频。
  4. IMU 与里程计的关键字段、数据变化与个人分析。
  5. 至少一个真实的调试问题：完整报错或现象、原因判断、尝试步骤与最终结果。

参考资料：幻尔 JetAuto 快速使用手册、ROS2 底盘运动控制课程。官方文档与实机镜像版本可能存在差异，所有包名、节点名和话题名以实际设备为准。
